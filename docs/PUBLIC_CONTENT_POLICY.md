# Public Content Policy

The `ironveilpress-site` repository is public by design. Every file is treated as publishable, searchable, and deployable. This policy keeps public storytelling useful without exposing private canon, production information, or contributor data.

## Public content may include

Public material may explain Iron Veil Press, The Threl, the Ashenfold setting, public module descriptions, public playtest instructions, approved MVP mechanics, public licensing statements, public release notes, and public community calls to action.

Public copy may describe Christian themes, moral tensions, spiritual struggles, redemption, Scripture-rooted worldbuilding, and elements of faith woven into the setting. It should invite participation without turning the site into a private design archive.

## Public content must not include

The site must not publish secret Warden lore, private military history, hidden affiliations, unreleased chronology, detailed Frey Wars history, a definitive meaning for the unresolved term “The Frey,” internal canon disputes, conflict audits, pass-on notes, private production comments, unpublished manuscripts, unreleased mechanics, contributor personal data, customer data, credentials, or private URLs.

## Rules and mechanics boundary

When public copy discusses Threl play, use the current approved MVP language. Prepared Phrase cards carry their own level, cost, DC, theological tag, effect, and Failure Echo. Ordinary play uses one roll, a six-box Strain track, named Conditions, Failure Echoes, Force It at 6 Strain, and Short/Long Rest recovery.

World Drift scoring, glyph arithmetic, Backlash tables, Vertical Friction, Linguistic Friction, and other advanced systems may appear only when explicitly labeled as design-layer, advanced, or optional material. They must not be presented as ordinary MVP requirements.

## Public versioning

Every public playtest link should identify a version or release date. A public page should explain what is experimental and link to the changelog. If a file is replaced, preserve the old release only in an archive location that is clearly labeled and does not compete with the current download.

## Review checklist

Before merging public content, confirm that the material is approved for public use, has no internal file paths, contains no private lore, uses current rules language, includes rights and attribution information for every new asset, has accessible text equivalents for important visual content, and links only to public destinations.

When the boundary is uncertain, keep the material private and request an owner decision. The absence of a secret label is not proof that content is public.
